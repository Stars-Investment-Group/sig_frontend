# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev        # Vite dev server (client/ as root) — http://localhost:5173
npm run build      # Production bundle to dist/public
npm run preview    # Serve the built bundle
npx tsc --noEmit   # Typecheck (no script alias exists)
```

There is **no test runner and no linter** configured — don't claim tests pass; verify UI changes in the browser.

`npx tsc --noEmit` is **clean** since the dead-code removal of 2026-09-30. Keep it that way: any error it reports now is one you introduced.

## Architecture

**The app runs on static mock data by default, and reads the real backend when `VITE_USE_API=true`.** The React SPA is still the whole product — there is no server in this repo — but since 2026-10-15 a live NestJS API can supply the figures, with the mocks as the floor. See **The API layer** below. Without that flag no network call is made at all, so the static mode stays strictly offline.

- Vite `root` is `client/`, so `client/index.html` → `client/src/main.tsx` is the entry. Aliases: `@/` → `client/src/`, `@shared/` → `shared/`, `@assets/` → `attached_assets/`. Always import via aliases, never relative `../..` paths.
- `client/src/App.tsx` is the router (wouter `<Switch>`): every page is `lazy()`-loaded and wrapped in `AppLayout`. Adding a page means adding both the lazy import and the `<Route>`.
- **The country file is a tab container**, not a page: `/countries/:code/:tab` (three `<Route>`s, all rendering `CountriesPage`, which canonicalises the URL). The tab list lives in `client/src/components/country/tabs.ts` — that registry is the single source of truth for the tab bar, the routing and the default slug, so adding or renaming a tab is a one-line change. Each tab component is itself `lazy()`-loaded, so the six tabs are six separate chunks.
- `/themes` is the Themes Explorer (module 11, specified 2026-10-01). A theme is a **cross-cutting** grouping of indicators, countries and signals. The open theme lives in `?code=`, so the drill-down is shareable. Its data layer is `client/src/data/themes.ts`: country scope is a **predicate** over `STATIC_COUNTRIES`, not a frozen list, and signals are **computed** from real series and regimes — never write a signal by hand, it would show an alert nothing justifies. A theme's score comes from its own indicators and is `null` (shown as "Non noté") when none are in the catalogue yet; don't substitute the perimeter's average, which doesn't depend on the theme.
- `/compare` is the multi-country comparison (P3). Its selection lives in `?codes=CIV,SEN,USA`, so the URL *is* the saved comparison — don't move that into component state. It has **no sidebar entry on purpose**: `SIG Tracker Menu Bar.pdf` governs navigation and doesn't list one; the page is reached from the country file's *Comparer* button and from global search.
- `/rating`, `/qualitative`, `/quantitative` and `/trends` are **redirects** to the matching country tab. Their old page components (`pages/Rating.tsx`, `pages/QualitativeAnalysis.tsx`, `pages/QuantitativeAnalysis.tsx`, `pages/Trends.tsx`) are no longer rendered and are on the deletion list.
- `client/src/components/layout/AppLayout.tsx` owns the persistent sidebar + header and is the de-facto source of truth for which routes are *reachable by users*. `/quantitative`, `/qualitative`, `/rating` and `/trends` are registered but not linked — they are redirects. `/overview` was **deleted on 2026-10-09**: it was an unlinked, thinner duplicate of `/` whose numbers disagreed with it.
- Page components live in **two** places since the 2026-10-09 cleanup: the dashboard set in `client/src/components/dashboard/` (`IndicatorsPage`, `MarketsPage`, `PolicyTrackerPage`, `CalendarPage`, `AlertsPage`, `WatchlistPage`, `ReportsPage`, `ScreenerPage`, `SettingsPage`, `RegimesPage`, `ThemesPage`, `ComparePage`, plus `RegionsPage`/`CountriesPage`/`DataExplorerPage`) and the six country tabs in `client/src/components/country/`. `client/src/pages/` holds only `GlobalOverview` (planche P1) and `not-found`, and `client/src/auth/` holds `LoginPage` plus the access layer (see **Who can see what**). Dashboard pages use **named** exports, hence the `.then(m => ({default: m.X}))` in the lazy imports.

### Data layer

All displayed data comes from these modules. They remain the **fallback** for every wired page, and the only source when `VITE_USE_API` is unset.

- `client/src/data/mockData.ts` — `STATIC_COUNTRIES` (**24**, including the full 8-member UEMOA), `STATIC_INDICATORS` (**24**, each carrying `family`, `block`, `shortName` and a polarity), `STATIC_OBSERVATIONS` (vintaged), `STATIC_REGIMES` (one per country — no exceptions, see the lookup rule below), `STATIC_RATINGS`, plus the accessors `getStaticHistory`, `getVintages`, `getRating`, `getRegime`. Typed against `shared/schema.ts`. Series are generated per country **and** per indicator (`seriesShape`): a shape shared across countries made diffusion and trend matrices identical everywhere, which read as data but was an artefact — don't reintroduce a common curve.
- `client/src/data/comparison.ts` — normalisation for the compare page. Two scales live side by side on purpose: the **z-score** of the detail table is relative to the current selection (removing a country legitimately moves everyone else), while the **0-100 score** of the heatmap is normalised over the whole universe with 10% padding, so the grid does not force an exact 0 and an exact 100 into every column. Both are **orientation-adjusted** so a positive score always means "better" even for inflation or risk where low is good. If you change one, fix the caption that describes it — a figure and its legend cannot disagree.
- `client/src/data/countryProfile.ts` — `getCountryProfile(code)` assembles the consolidated per-country view (KPIs, regime lines, growth path, forecast table, peers, house view) from the typed sources. **Every country tab consumes this and nothing else**, so the country selector actually drives the whole page. It takes a second argument, `ProfileSources` (regime, rating, history), whose static implementation `STATIC_SOURCES` is the default — **this is the seam**, and `client/src/api/countrySources.ts` is the API-backed implementation. It is a parameter and not a module-level store on purpose: this function is called *inside loops* by the screener, the watchlist, Themes and Settings, and a store that only the country file filled would leave those pages reading something else than it. Keep derivations here rather than inside tab components. The function **throws** on an unknown code — it used to `?? STATIC_COUNTRIES[0]`, rendering the first country's figures under the requested country's flag.
- `client/src/data/mockDashboard.ts` — the remaining per-widget fixtures. **Shrinking by design**: anything expressible from `mockData` is derived there instead (`topMovers`, `regionBlocks`, `countryWatchRows` now are). Eleven dead fixtures and eight orphaned interfaces went on 2026-10-09; several carried country figures that contradicted the profiles. Before adding a fixture with a country number in it, check whether `getCountryProfile` already answers.
- `client/src/data/watchlist.ts` and `client/src/data/alerts.ts` — the two user-facing lists. Only **membership** is fixture; every displayed figure is read from the profile. `alerts.ts` also holds the shared read-state (`useAlerts`, `markAllAlertsRead`) because the header bell counts unread — it used to show a hard-coded `3` that never moved.
- `client/src/data/markets.ts`, `client/src/data/policy.ts`, `client/src/data/reports.ts` — the fixtures of Marchés, Tracker de Politique and Rapports, moved out of the page components on 2026-11-13 so the injector and the page read one source. See **Fixtures belong in `data/`** below.
- `client/src/data/calendar.ts` — the **one** event list. It carried a contradiction: twelve entries lived inside `CalendarPage` and six hand-written ones in `mockDashboard`, and the two overlapped without agreeing — the home card announced the FOMC on 28 July while the calendar put it on 2 September, both visible at once. `CALENDAR_EVENTS` is now the single source; the home card shows its first six rows. Both consumers go through `useCalendarEvents()` (`client/src/api/calendar.ts`), so they cannot diverge again, on the API or on the fallback. The date, time, title and importance are editorial; the **previous value is an observation**, resolved through `series` from `getStaticHistory`, so a figure on the calendar cannot disagree with the rest of the app.
- `shared/schema.ts` is the **type contract for the 10 backend modules** — plain TypeScript, no Drizzle: `Country`, `MacroIndicator`, `MacroObservation` (carries `vintageDate` / `releaseDate` / `isForecast`), `MacroRegime`, `CountryRating` with its 7 `PillarKey` pillars, `EconomicEvent`, `EconomicAlert`. No database is connected. Keep mock data conforming to these types so the eventual API swap is mechanical.
- `client/src/data/world-110m.json` — Natural Earth 110m TopoJSON, vendored from `world-atlas@2.0.2` (public domain) so the map needs no network. See **Maps** under Conventions.

- **Never `?? LIST[0]` on a lookup by key.** `getRating` fell back to `STATIC_REGIMES[0]` for a country with no regime, so eight newly added countries silently inherited the United States' rating and six of them scored an identical 67/100. Nothing appeared in the console and the typecheck was clean. `getRegime(code)` now throws. A blank page beats a borrowed figure.

### The API layer (added 2026-10-15)

`client/src/api/` is the HTTP client, written against the live NestJS backend and verified against a running server. Nothing here is speculative: every envelope and field name below was confirmed by calling the route.

```bash
npm run check:api        # probes 27 routes, reports shape mismatches and empty tables
CHECK_TIMEOUT_MS=120000 npm run check:api    # when the database is cold
npm run seed:neon        # injects the static dataset into the backend's database (modules 1-14)
```

- `client.ts` — `apiFetch`, the base URL from `VITE_API_URL` (default `http://localhost:3000`), the Bearer header, and the edge converters (`toNumber`, `toDate`, `toPeriod`, `toIsoDay`). It deliberately does **not** send `credentials: "include"`: the backend answers `Access-Control-Allow-Origin: *` together with `credentials: true`, a combination browsers reject. The abort timeout is 30 s (`VITE_API_TIMEOUT_MS`) — generous on purpose, because the fallback is already on screen, so a long timeout delays nothing and lets a sleeping database wake up. A suspended Neon endpoint takes ~28 s to answer.
- `types.ts` — the wire types mirroring `prisma/schema.prisma`. `WireDecimal = string`.
- `macro.ts` (modules 1–4), `analytics.ts` (modules 5–9) — the adapters. They also hold the derivations the database does not store: risk/inflation/growth *levels* from scores, and `previousValue` / `change` / `changeDirection` over a sorted series.
- `useApiData.ts` — **the contract for every wired page.** The fallback is the *floor*, not an alternative: during loading, on a network error, on a 404, or when `VITE_USE_API` is unset, the page shows its static data. A page therefore cannot empty itself because a route is slow. `sourceAttr(fromApi)` puts `data-source="api" | "mock"` on the container — invisible on screen, but a page that says nothing lets you believe it reads the API when it is serving its fallback. Assert on it rather than trusting a green render.
- `overview.ts` (P1 KPI strip, Top Movers), `regimes.ts` (module 4), `calendar.ts` (module 9), `countrySources.ts` (the country file), `universeSources.ts` (the four pages that iterate countries), `explorer.ts` (Data Explorer), `indicatorSeries.ts` (the indicator matrix and the compare page), `regions.ts` (module 8 **and** the `/regions` page), `markets.ts` / `policy.ts` / `reports.ts` (modules 12–14), `auth.ts` (the session) — the per-feature hooks.
- `explorer.ts` is the only consumer of the **vintage** dimension: `/macro-data/:c/:i` gives the series at its final vintage, `/macro-data/:c/:i/vintages` all the revisions. Both return the same 26 raw rows over 12 periods, so the second is read *without* `toObservations`' reduction — the stack of vintages is precisely what that page shows. Its "3M / 6M / 1Y ago" columns are not earlier periods, they are earlier **states of knowledge** of the same period.

**Division of labour.** The API owns the figures it stores; the fixture owns everything the schema has no column for. `global_kpis` has no sparkline, no icon, no subtitle; `/global-kpi/movers` has no regime momentum; `events` has no "previous value" and no zone label ("UEMOA", "Zone euro" are not country names). Merging keeps the mockup intact. Where a merge reformats a number, derive the precision from the fixture string — `toFixed(1)` on a rate displayed as `4.25` would silently change the layout.

**Traps confirmed against the server** — each of these produced a wrong screen with a clean typecheck:

- **No route deduplicates vintages.** `/macro-data/:country/:indicator` sorts by period then `vintageDate desc` but does not reduce; `/macro-data?country=` returns the table as is. July 2026 exists at vintages 2026-04, 2026-01 and 2025-07, so taking the last row of the sort returned the *oldest* estimate — the Ivorian file announced 6.2% growth where the current value is 5.6%. `toObservations` now reduces to the final vintage. Revision history needs all vintages and goes through `fetchVintages`, which returns raw rows.
- **Scores: the database stores on 100, the front contract reads on 10.** One scale per side, divided once in the adapter. Getting this wrong shows `650` on a `/100` gauge.
- **The envelope is not uniform.** Most routes return a bare array; `/macro-data/:country/:indicator` wraps its series in `{ countryCode, indicatorCode, series }`; `/country-screener` paginates under `{ data, pagination }`; `/global-kpi/movers` and `/heatmap` wrap under a named key. Unwrap per route, and never assume from a neighbour.
- `/country-rating/:country` exposes `pillars`, not `pillarScores` as the column is named. `/global-kpi/movers` names its fields `currentScore` and `previousScore`, not `overallScore`.
- `/global-kpi/movers` needs **two** rating reviews per country and silently skips a country with one. A country missing from the list is not a stable country — it is a country whose movement is unknown.
- `macro_regimes` has **no unique constraint**: two current regimes for one country are possible, which would show a country twice on the map and in the count. `useRegimes` keeps the first per country.
- `/calendar/events/upcoming` filters on today's date, so it is empty against the frozen mock calendar (events dated August–September 2026). Use `/calendar/events`.

**Fixed by the backend team, verified 2026-11-13** (both were blockers above; kept here because the fix is what to rely on):

- **CORS.** `main.ts` now treats an unset value and `*` alike as "any origin" (`!corsOrigin || corsOrigin === '*' ? true : corsOrigin.split(',')…`). Setting `CORS_ORIGIN=*` no longer breaks it. The OVH domain can be added as a comma-separated list.
- **The screener's N+1.** `country-screener` now does `Promise.all([macroData, ratings, regimes])` instead of ~145 sequential queries. `/country-screener` answers in seconds and no longer starves the pool. The front still goes through `getCountryProfile` — the page already computed its rows client-side, and re-pointing it is optional rather than urgent.

**Known backend blockers** (raised with that team, not fixable here):

- **`GET /reports` answers 400 unconditionally** and can never succeed. `findAll(@Query() filters: CreateReportDto)` binds the *creation* DTO to the query string, and that DTO declares `category`, `startDate`, `endDate` **with no `class-validator` decorator at all**. The global `ValidationPipe` runs `forbidNonWhitelisted`, and since the TS target materialises declared fields, it sees three non-whitelisted properties *even with an empty query string* — hence `["property category should not exist", …]` on a bare `/reports`. The fix is one line per field (`@IsOptional() @IsString()`), plus renaming the DTO, since a Create DTO is the wrong shape for query filters. `/reports/featured` and `/reports/categories` take no DTO and answer 200.
- **The vintage migration is recorded but was never executed.** `20260906140000_add_vintage_to_economic_indicators` sits in `prisma/migrations/`, yet in `_prisma_migrations` its row has `applied_steps_count = 0` with `finished_at` set and no `rolled_back_at` — the signature of `prisma migrate resolve --applied`. The columns `vintage_date` / `is_latest` / `last_seen_at` do **not** exist, while `prisma migrate status` cheerfully reports "Database schema is up to date!". Consequence: `economic_indicators` keeps the old unique key `(provider, dataset, seriesCode, period)`, so **each resync overwrites the value instead of keeping the revision**. `main`'s `schema.prisma` also still lacks the three fields, so a `migrate dev` there would try to drop them.
- **The rate limiter is set to 10 requests per minute per IP** (`ThrottlerModule.forRoot({ throttlers: [{ ttl: 60000, limit: 10 }] })` in `app.module.ts`, applied globally as `APP_GUARD`). That is below what a single page costs: the home page alone fires five or six calls, so a visitor is throttled after two pages, and `/auth/refresh` 429s on an ordinary reload. Measured on 2026-11-21, not inferred — 429s on `/macro-data`, `/macro-regime` and `/auth/refresh` during a normal browse. It is also per **IP**, so everyone behind one NAT or one mobile carrier shares the bucket. The limit belongs per route group — strict on `/auth/*`, generous on the read routes — and much higher. The front now survives it (a 429 no longer closes the session), but the pages fall back to fixtures while it bites.
- `/global-kpi/movers` truncates at ten (`movers.slice(0, 10)` in `global-kpi.service.ts:120`, hard-coded, no parameter), so there is still no way to read the rating of all 24 countries in one call.
- `/regions/:code/heatmap` passes `code.toUpperCase()` to the `where` (`regions.service.ts`, three occurrences) while the stored regions are capitalised — "Africa", "Europe". Only "UEMOA", already uppercase, matches, so the route 404s on **four regions out of five**. `/regions` lists five; this one serves one. `regions.ts` deliberately does not call it and derives the five pillar columns client-side instead.

**Fixed since, verified 2026-11-15:** the screener asked for `inflation_rate` where the catalogue has `cpi_inflation`, leaving the inflation column `null` for all 24 countries with no error. `country-screener.service.ts` now reads `cpi_inflation`.

**The empty-array trap** — eight tables returned 0 rows on 2026-11-13 (`market_indices`, `sovereign_yields`, `market_conditions`, `market_hours`, `central_banks`, `policy_actions`, `global_policy_summary`, `reports`), and `npm run seed:neon` now fills them. The lesson outlives the fix: **`useApiData` does not protect against an empty array.** `[]` is `defined`, so it becomes the data with `fromApi: true` and the page renders blank. Every hook over a possibly-empty table must treat length 0 as an absence and return its fallback — `regions.ts`, `markets.ts`, `policy.ts` and `reports.ts` all do, and `markets.ts` does it **per block**, so one missing category does not empty the other two cards.
- `DATABASE_URL` needs `connect_timeout` raised (Prisma defaults to 5 s; opening a connection to Neon `us-east-2` from West Africa takes 8–28 s, and every route needing a new connection answers 400). The real question is the region: measured at 0.5–0.8 s per round trip, which is what makes the N+1 above fatal.
- There is **no bulk ratings route** — only `/country-rating/:country`. `rank`, `universe`, `changeSincePrior`, `outlook`, `watchStatus` and the pillar labels have no column and stay static.

**Three bulk shapes, chosen by what a page actually reads.** `/macro-data?country=X` gives one country's 624 observations (the country file); `/macro-data/latest` gives the last point of all 576 series (the four iterating pages); `/macro-data?indicator=X` gives one indicator across all 24 countries (the indicator matrix, the compare page's sparklines and normalised trends). The last one is what makes a 24-country matrix with real deltas and sparklines cost two to seven requests instead of twenty-four — `latest` alone would flatten every delta to zero and every sparkline to a point. `indicatorSeries.ts` fires those in batches of three: the backend's pool is narrow, and seven simultaneous calls starve it exactly as `/country-screener` does.

**Two kinds of sources.** `countrySources.ts` loads the full 624-observation history of **one** country for the country file; `universeSources.ts` loads only the last value of all 576 series (`/macro-data/latest`) plus the regimes, which is all the screener, the watchlist, Themes and Settings display — they iterate 24 countries and show no series. Two bulk requests instead of twenty-four.

The screener is wired through `getCountryProfile`, **not** through `/country-screener`: that route is unusable (see blockers), and the page already computed its rows client-side. The N+1 is bypassed rather than waited for.

**What is still static, and why.** Rapports serves its fixture because `GET /reports` is unconditionally 400 (see the blockers); the hook calls it anyway, so the page lights up by itself the day it is fixed. The Themes *list* makes no request — only a theme's detail view reads the API. One home-page block of six stays on its fixture. And the composite rating score on the four iterating pages. No route returns the rating for all 24 countries — `/country-rating/:country` serves one and `/global-kpi/movers` truncates at ten (`movers.slice(0, 10)`, hard-coded, no parameter). Calling it per country from the browser would reproduce the very N+1 we criticise, client-side, for one column. The figures agree today only because the database was seeded from the fixtures; the day real ratings are computed, that column will diverge. The ask is tiny: a `?limit=` on `/global-kpi/movers`, or a parameterless `GET /country-rating`.

Also still on fixtures, labelled as such on screen: the country file's Policy & Events timeline and Market Snapshot.

### Who can see what — the three access levels (2026-11-21)

`Acces_Pages_Tracker.pdf` assigns every page a level, and `client/src/auth/access.ts` is the **single source of truth** for it, the way `components/country/tabs.ts` is for the tabs. The router, the sidebar and the gates all read it; changing a page's level is a one-line change.

| Level | Rule | Pages |
|---|---|---|
| **A** public | everything, no account | Global Overview, Indicators, Markets, Calendar |
| **B** public + private detail | the page renders; its *detail* asks for an account | Régions, Countries, Themes, Policy Tracker |
| **C** private | nothing without an account; redirect to `/login?next=…` | Régimes, Alerts, Watchlist, Reports, Data Explorer, Screener, Settings, `/compare` |

- **`accessOf()` defaults to `C`.** A page added without being registered closes rather than opens, so the oversight is visible immediately instead of quietly publishing a screen that was meant to be reserved.
- **Why the gate is load-bearing, and not merely cosmetic.** Without it a private page opened with no token would *not* go blank: the protected routes answer 401, `useApiData` falls back, and the page renders **completely filled with fabricated figures**. The fallback — a virtue everywhere else — is the trap here. The gate is also *not* a security boundary: anything sensitive stays behind the backend's JWT guard. It protects the experience, not the data.
- **Where the B frontier runs is a per-page judgement**, so it lives in the page, not in the router: Régions locks the 24-country table and keeps the five regional blocks; Countries keeps *Summary* public and locks the five analysis tabs; Themes keeps the grid and locks a theme's detail; Policy Tracker keeps the banks and locks the decision log. These are readings of "fiche détaillée / données approfondies", not lines of the document.
- `<PagePrivee>` (level C) and `<DetailPrive>` (level B) are in `client/src/auth/Gate.tsx`. The reserved content is **not rendered at all** — not hidden by CSS — so it is not in the DOM. Both pose `data-access="granted" | "locked" | "pending"`, and `AppLayout`'s `<main>` carries `data-page-access` and `data-session`: the whole table above is assertable in one browser sweep, the way `data-source` makes the API/mock split assertable.
- **The third state is the one that gets forgotten.** While the session reopens, the answer is neither yes nor no. Returning "locked" would flash "demande un compte" at a signed-in user on every page load. `useAccessState()` returns `pending` for that, and the gates render a skeleton.
- **Offline mode is deliberately ungated.** With `VITE_USE_API` unset there is no backend, so no accounts can exist and nothing real is exposed — the static mode makes no request at all. `status` is then `"offline"`, every page opens, the header shows a "Démonstration" pill and `/login` says plainly that no account can be created. A login screen that cannot succeed is worse than none, and this is what keeps the published GitHub Pages demo usable.
- **The session.** `client/src/api/auth.ts` holds the five routes; `AuthContext` holds the state. The access token lives **in memory only** and expires in 1 h; the refresh token lives in `localStorage` and lasts 7 days. That is not the best place — an XSS would read it — and the right one is an `httpOnly` cookie, which this backend cannot set while it answers `Access-Control-Allow-Origin: *` with `credentials: true`. Raised with that team.
- **One renewal at a time, and a refusal is not a failure.** The backend *rotates* the refresh token and treats reuse as an attack (`SECURITY_TOKEN_REUSE_DETECTED` → 403), so two concurrent refreshes would log the user out; `renewal` keeps the single in-flight promise. And only **401/403** closes the session: a 429, a 5xx or a dropped network suspends it and retries with backoff, keeping the stored token. Measured on 2026-11-21 — eighteen navigations in a row trip the backend's rate limiter, and the session was dying from it.
- `apiFetch` retries **once** on a 401, after asking `AuthContext` to renew (`setReauthorizer`). Never a loop.

### The BCEAO series — the only measured data, and the page that showed them (2026-11-21)

`economic_indicators` holds **4 991 real observations** from the BCEAO via DBnomics. Everything else in the database carries `source = 'SIG-MOCK'` and was fabricated to connect the pages. Never merge the two without a label.

**The page that displayed them was removed on 2026-11-21**, on the instruction of `Acces_Pages_Tracker.pdf` ("BCEAO Data — page à supprimer"). `client/src/api/uemoa.ts` and `client/src/components/dashboard/UemoaPage.tsx` went with it, along with the sidebar entry — which was the one deliberate departure from the governed menu, so the menu and the code now agree again. **Both files are intact at commit `9bc4b79`** and can be restored as they were; the facts below are kept because they are what any future reuse has to deal with, and because the data itself is still in the database and still the only measured thing in it.

- **119 series**: `GET /uemoa/series` returns 119 rows, `GET /uemoa/indicators` the observations, both `@Public()`. 15 indicators × 9 perimeters (the 8 UEMOA members + the "Ensemble UMOA" aggregate): PIBN 3×9, IMECO 7×9, IHPC 9, TAUXINFL_A 9, TOFE 9, TC_A 2 — total 119.
- They live in `economic_indicators`, **not** `macro_data`, and four things make them incompatible with the `MacroObservation` contract. Pouring them into the existing KPIs would print 2024 CFA-franc billions under a label announcing a 2026 percentage.
  1. **The period is a bare year** — `"2024"`, not `"2024-07"`. The series are annual.
  2. **They stop at 2024.** The front shows points through 2026. DBnomics carries nothing more recent for the BCEAO; 2025–2026 has to come from the Bank's own portal — see **Completing the BCEAO series** below.
  3. **Country codes are alpha-2** (`CI`), the app is alpha-3 (`CIV`), and the UMOA aggregate has a **null** `country`.
  4. **The units are not the KPIs' units.** Most are *levels* in billions of CFA francs — Côte d'Ivoire's 2024 fiscal balance is `-2120.6`, not `-3.2`. Only inflation, the current account as a share of GDP and the exchange rates are ratios.
- The indicator identity is `seriesCode.slice(3)`: a BCEAO code is a three-letter country prefix plus a shared suffix, so `AAASR1015A0BP` and `KKKSR1015A0BP` are the same indicator for Côte d'Ivoire and Senegal.
- `GET /uemoa/indicators` with no filter returns all 4 991 rows — it is **not paginated**. Always filter. The UMOA aggregate cannot be targeted by `?country=` (the route filters on equality and the column is null).
- **There is no vintage dimension in this database**, despite the pipeline branch and its migration — see the blocker above.

#### Completing the BCEAO series beyond 2024 — EDEN, probed 2026-11-21

DBnomics stops at 2024. The source for 2025–2026 is the Bank's own database, **EDEN** — `https://edenpub.bceao.int/`, free, no account, ~15 300 series. It is a PHP form application from around 2010, not an API, but it **is** scriptable, and the chain below was exercised end to end:

1. `GET /` once, **keeping the `PHPSESSID` cookie**. Without the session every endpoint answers an empty `<table></table>`, which reads exactly like "no data" — that one detail is what makes the thing look dead when it is not.
2. `POST secteursDAO.php` with `idSecteur=<code>` → the sub-sectors. The codes are **alphanumeric, not numeric**: `SR` real, `SF` monetary and financial, `FP` public finance, `SE` external, `SS` social. `idSecteur=SR` returns `SR1` Comptes nationaux, `SR2` Production, `SR3` Prix.
3. `POST variablesDAO.php` with `idSousSecteur=…&idLocalite=…&idFrequence=…` → the variable catalogue, as an HTML table of code + label. `SR3` at frequency `M` returns **98 monthly variables**, among them `SR3017M0BP` — "Indice des prix à la consommation".
4. `POST rapport.php` with `secteurs`, `sous_secteurs` and `listVarsMultiple` → the extraction itself (HTML, or the UI's Excel export).

Three consequences worth having in mind before anyone plans this work:

- **EDEN carries monthly and quarterly frequencies** (`J H M T S A`). The 119 series in the database are annual because *DBnomics* only republishes the annual ones — not because the BCEAO only produces those. Going to EDEN is therefore not merely "2025 and 2026": it can also turn an annual series into a monthly one, which is what the pages actually display.
- **The coding system is the same.** `SR3017M0BP` has the structure of the stored `AAASR1015A0BP`: a three-letter country prefix plus a shared suffix. The `seriesCode.slice(3)` identity rule holds across both sources, so EDEN series slot into the existing catalogue rather than beside it.
- **The portal serves nine unprocessed `<php echo …?>` tags** (a `<php` typo instead of `<?php`), one of them inside the sector `<select>`, so that dropdown arrives malformed in the HTML. Together with the silent-empty-without-a-session behaviour above, this is a plausible explanation for the access difficulties reported by the data team — worth checking before blaming a network or a browser.

### Fixtures belong in `data/`, not in the page (2026-11-13)

Marchés, Tracker de Politique and Rapports held their fixtures as **module-private consts inside the `.tsx`**, so `scripts/seed-neon.mjs` could not read them — and a page cannot be wired against a table seeded from something else. They now live in `client/src/data/markets.ts`, `policy.ts` and `reports.ts`, read by the page *and* by the injector. That is what makes the falsifiable test hold for these three pages too.

- `policy.ts` exports **functions**, not constants: `centralBanks(src)`, `recentActions(src)`, `globalPolicySummary(src)` take a `PolicySources` (history + regime) defaulting to the static one. `BANK_SEEDS` carries only what the database cannot say — the bank's name, its zone, the inflation target, the next meeting date. The policy rate, observed inflation, the six-month path and the stance are **read from the series**, which is why the page can no longer announce the BCEAO at 3.00 % while the catalogue gives 5.2 % for Côte d'Ivoire.
- `mockDashboard.ts` gained `buildRegionBlocks(regime)` and `buildCountryWatchRows(regime)` for the same reason — the `/regions` page had stayed static while the home page's regional blocks were wired, so two neighbouring screens read two sources. Both derive entirely from the regimes, so `/regions` adds **no request**: `/macro-regime` is already cached by the home map. `regionBlocks` / `countryWatchRows` remain as the static defaults.
- **Formatting round-trips must be character-exact.** The database stores `5482`, the mockup shows `5 482`. `commeLaFixture` reuses the thousands separator *as written in the fixture*: re-injecting a non-breaking space where the fixture has an ordinary one looks identical on screen and differs in the bytes, so a test comparing the two modes fails with nothing visible to explain it. `commeVariation` is separate because `commeLaFixture` only emits a `+` when the reference had one — right for a value, wrong for a change, where a rise whose fixture was a fall would render unsigned.
- `/policy/actions` names its bank `bankCode`, but that is the **bank's** code (`ECB`), not the country's (`EMU`). `BANK_CODE` in `data/policy.ts` is the single translation point, in both directions.

### Where the env file goes (fixed 2026-11-13)

Vite reads env files from `root`, which is `client/`. `vite.config.ts` now forces `envDir` onto the repo root so that `.env.example`'s own instruction is true. Before that, a file placed at the root was **never read**: `VITE_USE_API` stayed undefined and the app served its mocks with no signal whatsoever — all fourteen pages reported `data-source="mock"` with a populated `.env.local` sitting at the root. In pre-production that would have shipped a site on fabricated data, indistinguishable from a connected one.

Use `.env.development.local` for a local backend, **not** `.env.local`: Vite loads the latter in *every* mode, `build` included, so `http://localhost:3000` would be frozen into the production bundle. (`http://localhost:3000` does appear in the bundle regardless — it is the hardcoded default in `client.ts`; what matters is that `USE_API` compiles to `!1`.)

A **separate team** owns the backend in its own repo — `Stars-Investment-Group/backend_tracker` (NestJS 11 + Prisma 5.4 + PostgreSQL 17 + Redis, pnpm, public on GitHub). All 27 probed routes answer; `npm run check:api` is the current record of which.

- The API returns **raw Prisma records in camelCase** (`seriesCode`, `fetchedAt`) — the `snake_case` claim in `docs/AUDIT_BACKEND_INTEGRATION.md` §3.1/§4 is wrong, so no case-conversion layer is needed. `Decimal` fields still arrive as strings, and list endpoints are **unpaginated**.

Never present them as macroeconomic facts. Two `DELETE ... WHERE source = 'SIG-MOCK'` remove them. **The exception is `economic_indicators`** — the 4 991 BCEAO observations, which are real; see **The BCEAO series**. `market_hours` is a third case: public opening times, factual, and the table has no `source` column to mark them with.

## Conventions

- **Theming**: light/dark via CSS custom properties in `client/src/index.css` (`:root` and `.dark`), mapped into Tailwind in `tailwind.config.ts`. `hooks/useTheme.ts` toggles the `dark` class on `<html>` and persists to `localStorage["sig-theme"]`. Style with semantic tokens (`bg-card`, `text-muted-foreground`, `border-border`, `bg-sidebar`) plus `dark:` variants where a raw palette color is unavoidable. `terminal-*` classes appear in older docs and do not exist — never reintroduce them.
- **Colour tokens are stored as bare HSL channels** (`--primary: 215 85% 32%`) and mapped as `hsl(var(--primary) / <alpha-value>)`. This is load-bearing, not cosmetic: it is what makes opacity modifiers work. Writing a full `hsl(...)` in the variable makes `bg-primary/70` compile to `hsl(hsl(215 85% 32%) / 0.7)`, which the browser discards **silently** — backgrounds vanish, `fill-*` falls back to black, and nothing appears in the console. The repo ran that way until 2026-09-30 and ~40 tinted backgrounds were invisible. Never put a complete `hsl()` back into a token, and if a tint looks missing, check the computed `background-color` before assuming the class is wrong.
- **UI kit**: shadcn/ui (new-york, neutral) under `client/src/components/ui/`. Treat these as generated; compose rather than edit. **Only the 11 files the app actually reaches are kept** — `badge`, `button`, `card`, `checkbox`, `popover`, `select`, `switch`, `table`, `toast`, `toaster`, `tooltip`. The other 36 were deleted on 2026-09-30 along with the 28 packages they alone imported. If you need another shadcn component, re-add it with the CLI rather than restoring it from git history, so its dependency comes back with it.
- **Maps**: `components/dashboard/RegimeMapCard.tsx` is the only map. It renders a real choropleth with `d3-geo` (Natural Earth projection) over `client/src/data/world-110m.json`, a TopoJSON vendored from `world-atlas@2.0.2` so nothing is fetched at runtime. Both the projection code and the topology load via `import()` so the home page paints without them; `vite.config.ts` isolates them in a `geo` chunk. The topology identifies countries by **ISO numeric**, the app by alpha-3 — `client/src/data/worldGeo.ts` is the single translation point, never match on country name. Aggregates (`isAggregate`, e.g. `EMU`) have no outline: they colour their member countries, and individually-tracked members keep their own colour.
- **Charts**: Chart.js via `react-chartjs-2`. `components/TimeSeriesChart.tsx` and `components/TrendChart.tsx` are the shared chart components; `components/dashboard/Sparkline.tsx` for inline micro-charts. Don't add a second charting library. Hand-rolled SVG is used where Chart.js would be overkill (gauges, waterfall, fan) — **beware inverted y-axes**: a `<rect>` height computed as `y(high) - y(low)` comes out negative and logs a console error on every render.
- **Shared presentation primitives** live in `client/src/components/common/`: `DeltaBadge`, `SectionCard`, `KeyTakeaway`, `ScoreGauge` / `ScoreBar`, `Waterfall`, `Heatmap`. Compose these rather than re-deriving colour or polarity logic. Polarity is always an explicit prop — a rise is good for growth and bad for risk, inflation or unemployment, and the component can't infer that from the number. Country-specific vocabulary badges (outlook, momentum, watch status) are in `components/country/shared.tsx`.
- **Flags**: use `components/Flag.tsx` (hand-written SVGs). Emoji flags are intentionally avoided because they don't render on Windows/Chrome.
- **i18n**: `lib/i18n.tsx` provides `useI18n()` / `t(key)` for FR/EN/ES/PT/AR (AR is RTL). `AppLayout` carries its own separate `NAV_I18N` dictionary for sidebar labels. Existing pages mix hardcoded French and English strings; prefer `t()` for new copy.
- **Language**: code comments, docs and commit messages are in French. Follow that.
- **Bundle**: `vite.config.ts` hand-splits vendor chunks (`react`, `chart`, `ui-core`, `data`). Adding a heavyweight dependency means revisiting `manualChunks`.
